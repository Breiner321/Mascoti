# RF-03: Cierre de Sesión (Logout)

> **Semana:** 1 · **Ubicación en el código:** `core/auth`
>
> Lee también la sección **Adaptación a Firebase** al final: prevalece sobre el texto original cuando hay conflicto.

## Módulo

Módulo Transversal: Autenticación y Acceso

## Actor(es)

Usuario autenticado; Frontend; Backend/API

## Precondiciones

1. El usuario tiene una sesión activa.

## Disparador (Trigger)

El usuario pulsa la opción "Cerrar sesión" en el menú de configuración/perfil.

## Flujo Principal (Paso a Paso)

1. [Usuario] Navega al menú "Perfil" y pulsa "Cerrar sesión".
2. [Frontend] Muestra un diálogo de confirmación: "¿Estás seguro que deseas cerrar sesión?" con opciones Cancelar/Confirmar.
3. [Usuario] Pulsa "Confirmar".
4. [Frontend] Envía petición POST /auth/logout con el refresh token vigente para invalidarlo del lado del servidor.
5. [Backend/API] Revoca el refresh token (lo marca como inválido en la colección revokedTokens o equivalente en Redis/cache).
6. [Frontend] Cancela (unsubscribe) todos los listeners realtime activos (chats, notificaciones, agenda) para evitar fugas de memoria y accesos posteriores no autorizados.
7. [Frontend] Elimina el access token de memoria y el refresh token del almacenamiento seguro.
8. [UI] Redirige a la pantalla de bienvenida (login/registro).

## Flujos Alternativos y Excepciones

- Sin conexión al momento del logout: Si la petición al backend falla por red, el frontend igualmente limpia el estado local y tokens (logout local prioritario a seguridad del usuario), y reintenta la revocación en segundo plano cuando detecte conectividad.

## Postcondiciones

- El refresh token queda revocado y no puede reutilizarse.
- No quedan listeners activos ni datos sensibles en memoria del cliente.
- El usuario es redirigido a un estado no autenticado.

## ⚠️ Adaptación a Firebase (prevalece sobre el texto original)

- Logout = `GoogleSignIn().signOut()` + `FirebaseAuth.instance.signOut()`. No hay colección `revokedTokens` ni Redis.
- Los listeners se cancelan automáticamente porque los providers de Riverpod dependen del usuario autenticado (`authStateProvider`); al cambiar a `null` se eliminan.
- Se borra el token FCM del dispositivo en `users/{uid}/devices/{deviceId}`.
